# 任务书 · d7-theme-tokens（主题令牌与设计系统基础）

## 目标

建立**设计令牌层**：颜色语义、间距、字号、圆角等，作为所有视图的统一视觉基础。

## 定位

`src/theme/` 已有 `tool_titles.rs`（人话映射）与 `palette.rs`（命令表）。
本卡补充**视觉令牌**，形成完整的设计系统基础层。

**注意**：本层是「语义」不是「渲染」 —— 定义「什么颜色代表什么」，
不定义「怎么画」。这样换渲染后端也能复用。

## 你要做的事

### 1. 定义令牌结构

在 `src/theme/` 下新建 `tokens.rs` 与 `colors.rs`（或类似拆分）：

**颜色语义**（至少覆盖）：

| 语义 | 用途 |
|---|---|
| `background` / `surface` / `surface_hover` | 层级背景 |
| `text_primary` / `text_secondary` / `text_disabled` | 文字层级 |
| `border` / `border_focus` | 边框 |
| `accent` | 主色 |
| `danger` / `warning` / `success` | 语义色 |

**⚠️ 重要：状态色必须符合中文习惯**

```text
价格/数值上升 → 红色
价格/数值下降 → 绿色
```

这是中国市场的约定，与欧美相反。本产品虽非行情软件，但资源用量、配额消耗等
展示要沿用此约定，**不要照搬欧美配色**。

**尺寸令牌**：间距梯度、字号梯度、圆角梯度（用有语义的命名，不用 `spacing_7` 这类）

### 2. 亮/暗主题

定义两套令牌值，通过枚举或 trait 切换。

**关键约束**：令牌的**键（语义名）两套必须完全一致**，只有值不同。
有测试证明这一点 —— 漏一个键会导致暗色模式下某处变透明。

### 3. 与命令表文件的关系

`palette.rs` 现在是命令面板命令表（名字容易混淆）。
**不要重命名它**（不在你的 touches），但在报告里指出这个命名问题，
建议主理人后续把命令表移出 `theme/`。

## 交付物

1. `src/theme/` 下新增的令牌文件
2. `docs/theme-tokens-status.md`：令牌清单、亮暗两套的键一致性证明、实跑命令与退出码、缺口

## 边界

- 只改新建文件 + `theme/mod.rs` 追加 `pub mod`
- **不改** `Cargo.toml`、`src/theme/tool_titles.rs`、`src/theme/palette.rs`
- 不引入任何渲染依赖（本层是纯数据）

## 完成标准

1. 颜色/尺寸令牌有语义命名，不是 `color1`/`size1`
2. 亮暗两套令牌**键完全一致**，有测试证明
3. 状态色符合「涨红跌绿」中文约定（在报告里明确写出这条约定）
4. 本层零渲染依赖（`cargo test` 不开 `ui` feature 即可测）
5. 门禁四项全绿
