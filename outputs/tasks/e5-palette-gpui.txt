# 任务书 · e5-palette-gpui（命令面板接线）

## 本卡定位：**把命令面板接到 GPUI（含快捷键）**

`ui/command_palette.rs`（398 行）+ `state/palette_state.rs`（296 行）+ `state/hotkeys.rs`（687 行）已有完整逻辑，本卡只做渲染与事件接线。

## 现状（先读这三个，别重写）

```rust
// ui/command_palette.rs
pub struct PaletteRow { /* 一行命令 */ }
pub struct CommandPaletteView { /* rows / query / selected / empty 等 */ }
pub fn render(state: &PaletteState) -> Option<CommandPaletteView>   // None = 面板关闭
pub enum PaletteKey { /* Up/Down/Enter/Escape/Char 等 */ }
pub enum PaletteAction { /* 派发命令 / 关闭 / 无操作 */ }
pub fn handle_key(state: &mut PaletteState, key: PaletteKey) -> PaletteAction
pub fn handle_hotkey(...)    // 快捷键 → 打开面板

// state/hotkeys.rs
// 快捷键注册表 + 冲突检出（含用户覆盖后产生的冲突）
```

**关键语义（不得违反）**：
- 命令按 `id` 派发，**不按标题**
- 面板打开时关键词被清空
- 上下选择边界不越界（首项上移不变、末项下移不变）

## 你要做的事

在 `crates/lengsuo-desktop/src/ui/palette_gpui.rs`（**已建占位**）实现：

1. `pub struct CommandPaletteGpui { state: PaletteState }`，`impl Render`
2. `render()` 返回 `None` 时不渲染任何东西（面板关闭）
3. 有值时渲染：
   - 半透明遮罩层
   - 搜索输入框（关键词）
   - 命令行列表：选中行高亮、命令标题 + 快捷键提示
   - 空结果文案
4. 键盘事件 → 转成 `PaletteKey` → 调 `handle_key` → 按 `PaletteAction` 处理：
   - `PaletteAction::Execute(id)` 之类的变体 → 走一个回调（本卡不真执行命令）
   - 关闭类 → 调用后不渲染
5. 快捷键触发打开：在 `PaletteState` 上调用已有逻辑，不新造注册表

### 规则 1：调研预算 ≤ 12 次调用

查 gpui-kit API 的工具调用**最多 12 次**，用完就必须开始写代码。

不需要提前把 API 查全 —— 编译器会告诉你缺什么。**先写一个能编译的最小版本，
再按报错补**。这比先调研后实现快一个数量级。

### 规则 2：增量编译，每 5-10 分钟必查一次

**每写完一个渲染分支，立刻跑一次**：

```bash
cargo check -p lengsuo-desktop --features ui
```

⚠️ 首次编译约 1-2 分钟（gpui 依赖已编译好，之后 10-30 秒）。
**不要攒到最后才编译** —— 上批 e1/e2 就是攒到最后，16 个错误一起爆，预算耗尽。

### 规则 3：先落最简可编译版本

顺序固定：

1. 写最小骨架（一个 `impl Render` + 一个 `div()`，先保证能编译）
2. 立刻 `cargo check` 确认
3. 逐个加渲染分支，**每加一个就 check**
4. 最后补测试与文档

**任何时候预算即将耗尽，就把当前能编译的版本提交下来** ——
宁可交一个 60 分但能编译的版本，也不要交一个 95 分但编不过的版本。
空改动（没写任何代码）等于这张卡白跑，会被 verify 判失败。

### 规则 4：verify 会拒绝空改动

主理人已修 `card_guard.verify`：**改动文件数为 0 直接判失败**，
`HEAD` 未领先 base 也判失败。所以「调研到底、一行没写」是必然作废的，
不要再试图这样交差。
