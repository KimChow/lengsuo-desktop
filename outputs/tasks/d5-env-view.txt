# 任务书 · d5-env-view（环境视图 + 分组）

## 目标

实现**环境管理**界面：环境卡片网格 + 分组 + 筛选 + 状态展示。
这是对标端语义的另一半（环境是产品核心对象）。

## 既有资产（先读，必须复用）

`crates/lengsuo-desktop/src/state/env_list.rs` 已有 `EnvListViewState`：

- `EnvEntry { id, name, raw }` —— 保留原始 JSON 供渲染取字段
- `EnvStatus` 四态：`Loading` / `Ready` / `Degraded` / `Failed`
- **判定次序 fail-closed**：先匹配先生效 → Loading → Failed → Degraded → Ready
- `invalid_count()`：解析失败条目计数（不静默丢弃的可见性）
- `apply_entries()` / `begin_load()` / `fail()` / `select()`

**本卡要在它之上扩展，不要重写。**

## 你要做的事

### 1. 扩展状态层

在 `src/state/` 下新建 `env_group.rs`（或类似），实现：

- **分组模型**：环境可归属分组（服务端下发 `group_id` / `group_name`）
- **筛选状态**：按分组筛选、按关键词搜索
- **分组的健康态**：某分组内有多少环境解析失败

**关键约定（对齐既有写法）**：

- 环境**未分组**是合法状态（不是错误），要有明确的表示
- 筛选后结果为空 vs 原始数据为空，**要能区分**
- 分组信息缺失时，不猜测归属（宁可归入「未分组」也不瞎猜）

### 2. 环境卡片渲染

在 `src/ui/` 下新建环境视图：

每张卡片显示：
- 环境名（缺失时显示明确占位，**不要显示 id 猜名字**）
- 状态（就绪 / 降级 / 异常）
- 所属分组

**降级态要可见**：`invalid_count() > 0` 时，界面必须显示「有 N 条数据读取异常」，
不能静默吞掉 —— 这是 `env_list.rs` 已经定下的约定。

### 3. 分组侧栏

左栏列出分组 + 每个分组的条目数 + 「未分组」项。

## 交付物

1. `src/state/env_group.rs`（或同类名）+ `src/ui/env_view.rs`
2. `docs/env-view-status.md`：文件清单、测试覆盖点、实跑命令与退出码、缺口

## 边界

- 只改新建文件 + `state/mod.rs` / `ui/mod.rs` 追加 `pub mod`
- **不改** `Cargo.toml`、`src/state/env_list.rs` 既有内容（可 `use` 它）
- 不做真实网络请求

## 完成标准

1. 复用 `EnvListViewState`，未重写既有逻辑
2. 「未分组」是合法状态，有测试
3. 筛选后为空 vs 原始为空，可区分，有测试
4. 降级态（有坏条目）在界面可见，有测试
5. 门禁四项全绿

## ⛔ 上游不可用时的行为（硬约束）

若你在执行中遇到以下任一情况，**立即停止重试并结束本轮**，不要反复重试、不要改写任务目标：

- `API Error: 403` / `Failed to authenticate` / `上游模型繁忙`
- `API returned an empty or malformed response` / `check for a proxy or gateway`
- 连续两次工具调用均因网络/网关错误失败

结束时的报告必须是：

```
STATUS: UPSTREAM_UNAVAILABLE
最后一次错误原文：<粘贴>
已完成的工作：<无 或 具体文件列表>
```

**理由**：历史上有卡因 403 空转 61 轮、零产物、整轮作废。宁可快速失败让主理人修网关，也不要把轮次消耗在重试上。**这不是你的错，如实上报即可。**
